# harness/orchestrator/

The decision loop. Fires every `polling_interval_seconds` (default 60).
Assembles the input JSON per SPEC §3.1, wraps it in the §3.3 prompt
template, calls the orchestrator model, parses the JSON action list,
dispatches actions through the bus.

## Files

| file          | role                                                      |
|---------------|-----------------------------------------------------------|
| `prompt.ts`   | Builds system + user prompts; enforces the leak policy    |
| `loop.ts`     | Timer + action dispatch                                   |
| `history.ts`  | Delegation history compression (see below)                |

## Leak policy (SPEC §3.3)

These tokens must never appear in a prompt the orchestrator sees:

- `"Bitburner"` (exact, case-insensitive)
- `"seed"` and the numeric seed value
- scoring rubric details beyond "maximize the team's in-game money"

The system prompt is fixed across all benchmarked models. The user
prompt is the serialized input JSON with sanitized field names — the
orchestrator sees `game_state`, not `bitburner_state`; it sees
`money`, not `total_money_before_and_after_seed_XYZ`. A grep-based
test in storage dumps `orchestrator-prompts.log` for post-run audit.

## History compression

Default: last 10 cycles verbatim + a rolling summary of older cycles
generated by the orchestrator model itself. The summary generation
piggybacks on normal cycle calls — when the orchestrator output
exceeds context, the loop appends a "summarize cycles N..M in one
paragraph" directive to the next call and stores the summary for
future context.

## Hang detection

If a cycle yields no decision for 10 minutes (inference hang, adapter
silence, whatever), fail the run. CLAUDE.md §"Failure Handling" rules
apply: partial artifacts commit with `status: "failed"`.
